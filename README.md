# ป.ป.ช.สพฐ.น้อย โรงเรียนภูเขียว

ชุดเว็บไซต์ภาษาไทย โทนขาว ม่วง และทอง สำหรับ GitHub Pages พร้อมฐานข้อมูล Supabase และระบบเจ้าหน้าที่ `admin` / `nacc` ไฟล์ทั้งหมดเป็น source code ที่แก้ไขต่อได้ ไม่ต้องใช้ Node.js หรือสั่ง build เพื่อเผยแพร่หน้าเว็บ

## เริ่มตรงนี้ก่อน

**สถานะเริ่มต้นเป็นตัวอย่างก่อนเชื่อมต่อฐานข้อมูล** โดย `config.js` ตั้ง `connected: false` ไว้ เพื่อไม่แสดงข้อมูลสมมติเป็นข้อมูลโรงเรียน และไม่เรียก API ก่อนสร้างตาราง ให้ทำตามลำดับนี้ แล้วเปลี่ยนเป็น `true` ในขั้นตอนเปิดใช้งาน

- **ฐานข้อมูล:** รัน `supabase/schema.sql` ใน SQL Editor ของโปรเจกต์ที่กำหนด
- **บัญชีแรก:** สร้างผู้ใช้ใน Supabase Auth แล้วรัน `supabase/bootstrap-admin.sql` หลังแก้ UUID
- **การจัดการบัญชี:** ติดตั้ง Edge Function `manage-users`
- **เชื่อมเว็บ:** แก้ `connected: true` ใน `config.js`
- **เผยแพร่:** อัปโหลดไฟล์ขึ้น GitHub แล้วเปิด GitHub Pages

ยังไม่ได้รัน SQL หรือติดตั้งฟังก์ชันในโปรเจกต์จริงของคุณ และยังไม่ได้สร้างบัญชี รหัสผ่าน รีโพซิทอรี หรือเปลี่ยน DNS ใด ๆ การทดสอบฐานข้อมูลและหน้าจอใช้สภาพแวดล้อมทดสอบแยกจากโปรเจกต์จริง

## ตั้งค่า Supabase

### สร้างฐานข้อมูล

เปิดโปรเจกต์ `baprjszsaixaexpyyovs` ใน Supabase Dashboard จากนั้นเปิด SQL Editor สร้าง query ใหม่ วางโค้ดทั้งไฟล์ `supabase/schema.sql` และกด Run ไฟล์นี้ออกแบบสำหรับติดตั้งครั้งแรก และครอบด้วย transaction เพื่อไม่ให้สร้างค้างเพียงบางส่วน

ถ้ามีตารางชื่อเดียวกันอยู่แล้ว ให้สำรองและตรวจโครงสร้างก่อน ห้ามลบตารางเดิมเพื่อฝืนรันสคริปต์ และอย่ารันซ้ำหลังติดตั้งสำเร็จโดยไม่ตรวจฐานข้อมูล สคริปต์ไม่ได้ทำหน้าที่ย้ายข้อมูลจาก Google Sheets โดยอัตโนมัติ

หลังรันสำเร็จ จะมีตาราง 16 ตารางตามชื่อที่ขอ โดยคงตัวสะกด `Home`, `mamberNACC`, `ANACC`, `Certificate`, `botton`, `anthority` และ `culecculum` ไว้ตามต้นฉบับ ชื่อที่มีตัวพิมพ์ใหญ่หรือภาษาไทยต้องใส่เครื่องหมาย `"` เมื่อเขียน SQL เอง

### สร้าง admin คนแรก

1. เปิด Authentication → Users → Add user / Create new user
2. กำหนดอีเมลเป็น `webmaster@pkjunior.local` และตั้งรหัสผ่านที่แข็งแรงอย่างน้อย 12 ตัวอักษรด้วยตนเอง
3. เปิด Auto Confirm หากหน้าต่างมีตัวเลือกนี้
4. คัดลอก User UID ของบัญชีที่สร้าง
5. เปิด `supabase/bootstrap-admin.sql` แทน `REPLACE-WITH-AUTH-USER-UUID` ด้วย UID จริง
6. กำหนด `username` ให้ตรงกับส่วนหน้า `@` ในอีเมล เช่น `webmaster` แล้วแก้ `name` เป็นชื่อผู้ดูแลจริง
7. รัน SQL ที่แก้แล้ว จากนั้นล็อกอินหน้าเว็บด้วย Username `webmaster` และรหัสผ่านที่ตั้งใน Auth

`pkjunior.local` เป็นรูปแบบชื่อบัญชีภายในของระบบนี้ ไม่ใช่อีเมลรับส่งจริง ระบบจึงไม่มีอีเมลกู้รหัสผ่าน ผู้ดูแลที่มีสิทธิ์ admin สามารถรีเซ็ตรหัสให้บัญชีอื่นได้ หรือเจ้าของโปรเจกต์สามารถแก้ใน Supabase Dashboard

อย่าใส่รหัสผ่านใน `admin.password` หรือไฟล์บน GitHub ชุดนี้ตั้งใจไม่สร้างคอลัมน์เก็บรหัสผ่านข้อความธรรมดา โดยตาราง `admin` เก็บเฉพาะ `id`, `username`, `name`, `role`, `active` ส่วนการตรวจรหัสใช้ Supabase Auth และตรวจสิทธิ์จริงที่ฐานข้อมูล

### ตั้งค่า Authentication

- **การสมัครเอง:** ปิด Allow new users to sign up สำหรับเว็บเจ้าหน้าที่ที่ไม่ต้องการเปิดลงทะเบียน
- **URL Configuration:** ตั้ง Site URL เป็น URL เว็บไซต์ GitHub Pages ของคุณ
- **รหัสผ่าน:** ตั้ง minimum password length ให้ไม่น้อยกว่า 12 ตัวอักษร
- **เซสชัน:** โค้ดเว็บไม่เก็บเซสชันลง localStorage หรือคุกกี้ จึงต้องล็อกอินใหม่หลังรีเฟรชหน้า เปิดแท็บใหม่ หรือเปิดเว็บใหม่

บัญชี `nacc` เพิ่มและแก้ข้อมูลเนื้อหาได้ทุกส่วน แต่จัดการผู้ใช้อื่นไม่ได้ บัญชี `admin` จัดการเนื้อหา เพิ่มผู้ใช้ และรีเซ็ตรหัสผ่านได้ ทั้งสองสิทธิ์เปลี่ยนรหัสผ่านตนเองได้โดยยืนยันรหัสปัจจุบันก่อน

### ติดตั้ง Edge Function จัดการผู้ใช้

หน้าเว็บอย่างเดียวไม่สามารถใช้ service-role key อย่างปลอดภัยได้ จึงแยกการสร้างบัญชีและเปลี่ยนรหัสของผู้อื่นไปทำบน Edge Function แทน โดยมีโค้ดตรวจ JWT ผ่าน `auth.getUser(token)` และอ่านสิทธิ์ `admin` จากฐานข้อมูลทุกครั้งก่อนทำงาน

วิธีผ่าน Dashboard:

1. เปิด Edge Functions แล้วสร้างฟังก์ชันใหม่ชื่อ `manage-users`
2. เลือกแก้ผ่าน Editor แล้ววางโค้ด `supabase/functions/manage-users/index.ts`
3. Deploy ฟังก์ชัน
4. ตั้ง Verify JWT / Enforce JWT verification เป็นปิดสำหรับฟังก์ชันนี้ เพราะโค้ดตรวจ JWT เองอยู่แล้ว
5. ห้ามลบการตรวจ `getUser(token)` และการตรวจ `actor.role === "admin"` ออกจากโค้ด
6. ตรวจว่ามี environment มาตรฐาน `SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` ฝั่งฟังก์ชัน โดยไม่คัดลอกค่าเหล่านี้ไปไว้ใน frontend หรือ GitHub

หากใช้ Supabase CLI อยู่แล้ว สามารถใช้คำสั่งด้านล่างจากโฟลเดอร์โปรเจกต์แทนได้ การปิด gateway verification หมายถึงโค้ดฟังก์ชันต้องรับผิดชอบตรวจผู้เรียกเองตามแนวทาง [Supabase Edge Function authentication](https://supabase.com/docs/guides/functions/auth)

```sh
supabase login
supabase link --project-ref baprjszsaixaexpyyovs
supabase functions deploy manage-users --no-verify-jwt
```

เมื่อมีบัญชี admin แล้ว ให้เปิด `#/admin/users` เพื่อเพิ่มบัญชี `nacc` หรือ admin เพิ่มเติม การแก้บัญชีเดิมเปลี่ยนได้เฉพาะชื่อและรหัสผ่าน ไม่เปิดให้ลบบัญชี เปลี่ยน Username หรือถอดสิทธิ์ผู้ดูแลผ่านหน้าเว็บ เพื่อป้องกันการลบ admin คนสุดท้ายโดยไม่ตั้งใจ

### Storage

SQL สร้าง bucket ชื่อ `public-files` สำหรับ PDF, JPG, PNG, WEBP และ GIF จำกัดไฟล์ละ 20 MB ทุกไฟล์เป็นไฟล์สาธารณะ และใช้ชื่อสุ่ม UUID เพื่อไม่เขียนทับไฟล์เดิม

เจ้าหน้าที่อัปโหลดไฟล์ใหม่ได้ผ่านสิทธิ์ RLS แต่หน้าเว็บไม่ได้ลบไฟล์ออกจาก Storage การนำไฟล์ออกจากรายการแนบเป็นเพียงการเอาการอ้างอิงออก หากต้องลบไฟล์จริง เจ้าของโปรเจกต์ต้องตรวจว่าไม่มีหน้าอื่นใช้งานก่อน แล้วลบผ่าน Storage Dashboard

ถ้าอัปโหลดบางไฟล์สำเร็จแต่บันทึกข้อมูลไม่สำเร็จ ระบบแจ้งเตือนว่ามีไฟล์ที่ยังไม่ผูกกับข้อมูล ควรตรวจ Storage ก่อนอัปโหลดซ้ำ ไม่อ้างว่ามีการย้อนคืนไฟล์โดยอัตโนมัติ

### เปิดการเชื่อมต่อหน้าเว็บ

เปิด `config.js` และเปลี่ยนบรรทัดนี้หลังติดตั้งส่วนฐานข้อมูลแล้ว:

```js
connected: true
```

URL โปรเจกต์และ publishable key ที่คุณให้มาใส่ไว้ในไฟล์แล้ว ไม่จำเป็นต้องใส่รหัสลับเพิ่มเติมใน frontend ห้ามใช้ `service_role`, `sb_secret_...` หรือ database password ในไฟล์นี้เด็ดขาด

## อัปโหลดผ่าน GitHub UI

### วิธีง่าย: Deploy from a branch

1. แตก ZIP ที่ได้รับ แล้วเปิดโฟลเดอร์ `pkjunior`
2. สร้าง repository บน GitHub ตามต้องการ โดยใช้ branch `main`
3. เลือก Add file → Upload files แล้วอัปโหลดไฟล์และโฟลเดอร์ภายใน `pkjunior` ให้ `index.html` อยู่ที่ root ของ repository ไม่ใช่ซ้อนใต้โฟลเดอร์ `pkjunior` อีกชั้น
4. ถ้าใช้วิธี branch ให้ไม่ต้องอัปโหลด `.github/workflows/pages.yml` หรือเอา workflow นี้ออก เพื่อไม่ให้มีการ deploy สองวิธีพร้อมกัน
5. ตรวจว่า `assets`, `vendor` และไฟล์ JS/CSS อัปโหลดครบ ถ้าอัปโหลด `.nojekyll` ไม่ได้ ให้สร้างไฟล์ชื่อนี้ผ่าน Add file → Create new file
6. เปิด Settings → Pages → Build and deployment → Source → Deploy from a branch
7. เลือก branch `main` และโฟลเดอร์ `/(root)` แล้ว Save
8. รอให้ระบบเผยแพร่ แล้วใช้ URL ที่ GitHub แสดงในหน้า Pages

ขั้นตอนเลือก branch และโฟลเดอร์อ้างอิงจาก [คู่มือกำหนด publishing source ของ GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) ไม่ต้องตั้งค่า build command สำหรับชุดไฟล์นี้

### ทางเลือก: GitHub Actions

หากต้องการใช้ workflow ที่ให้มา ให้อัปโหลด `.github/workflows/pages.yml` ด้วย แล้วตั้ง Settings → Pages → Source เป็น GitHub Actions ไม่ต้องเลือก Deploy from a branch พร้อมกัน Workflow ทำงานเมื่อ push ไป branch `main` หรือกด Run workflow เอง

หาก repository ใช้ branch ชื่ออื่น ให้แก้ `branches: [main]` ใน workflow ให้ตรง ไม่ต้องติดตั้ง dependencies เพราะไลบรารี JS ที่ใช้กับเว็บรวมอยู่ใน `vendor` แล้ว

### เส้นทางและโดเมน

เว็บใช้ hash routing เช่น `https://YOUR_USERNAME.github.io/YOUR_REPOSITORY/#/significance` เพื่อให้เปิดหน้าลึกและรีเฟรชได้โดยไม่ต้องพึ่ง server routing เส้นทางที่ให้มาในคำสั่งถูกเก็บเป็นชื่อเมนูหลัง `#/` และจดหมายข่าวใช้ `#/newsletter` แทน `#/make` ที่ซ้ำกับคำสั่ง

ไฟล์ `CNAME.example` เป็นเพียงตัวอย่าง ยังไม่ได้ผูก `pkjunior.nacc.obec.com` จริง ต้องได้รับอนุญาตจากเจ้าของโดเมนและตั้ง DNS/Custom domain ให้ถูกต้องก่อน อย่าเปลี่ยนเป็น `CNAME` จนกว่าจะมีสิทธิ์และพร้อมใช้งาน

## ใช้งานระบบเจ้าหน้าที่

- **หน้าแรก:** เพิ่มภาพใน “ภาพสไลด์” ปรับลำดับแสดง และเพิ่มประกาศตามช่วงเวลาเริ่ม/สิ้นสุด โดยเวลาเลือกในแบบฟอร์มเป็นเวลาไทย
- **ประกาศตามเวลา:** ฐานข้อมูลสร้าง `dateline` เป็นช่วงเวลาจาก `start_at` และ `end_at` และ RPC `active_announcements()` ใช้เวลาปัจจุบันจากเซิร์ฟเวอร์ ไม่พึ่งนาฬิกาผู้ชม
- **ปุ่มลัด:** ใส่รูปไอคอน ข้อความ และ URL หรือชื่อเมนู เช่น `คำสั่ง`, `make`, `#/make` ถ้าไม่ใส่ภาพ ระบบใช้ไอคอนเส้นแทน
- **เนื้อหาประวัติ:** มีแถบตัวหนา เอียง ขีดเส้นใต้ ชิดซ้าย กลาง ขวา รายการ และสีข้อความ หัวข้อเก็บแยกใน `title` เนื้อหาเก็บเป็น HTML ที่กรองแล้วใน `mag`
- **บุคลากร:** กำหนดปีการศึกษา พ.ศ. รูป ชื่อ ชั้น และตำแหน่ง หน้าเว็บแสดงเฉพาะปีล่าสุดและเส้นโยงลำดับตำแหน่งเป็นระดับ
- **ตัวแทนห้อง:** เพิ่มรายคนหรือนำเข้า CSV ระบบเก็บรหัสเป็นข้อความจึงรักษาเลขศูนย์นำหน้า และรัน `no` ต่อจากเลขสูงสุดภายในปีนั้น
- **ข่าวสาร:** ประเภทผูกกับเมนูแก้ไม่ได้ แนบ PDF/ภาพได้รวม 100 ไฟล์ ชื่อผู้บันทึกและวันเวลาจากเซิร์ฟเวอร์ไม่เชื่อค่าที่แก้จาก browser
- **เกียรติบัตร/ผลงาน:** ใช้ปฏิทินไทย พ.ศ. มีระดับรางวัล ภาพกิจกรรมที่เลื่อนแนวนอนได้ และเพิ่มช่องรายชื่อผู้รับรางวัล/ครูที่ปรึกษาได้
- **แผนงาน:** เสนอไม่ผ่านหรือรอพิจารณาจะเลือกดำเนินการ/แล้วเสร็จไม่ได้ การเลือกแล้วเสร็จต้องมีดำเนินการก่อน เงื่อนไขถูกบังคับทั้งหน้าเว็บและ SQL
- **หลักสูตร/ธรรมนูญ/กฎหมาย:** เพิ่มชื่อเรื่องและแนบ PDF สูงสุด 1 ไฟล์ต่อรายการ
- **งบประมาณ:** แสดง “รอพัฒนา” ตามขอบเขตที่ให้มา ไม่ได้สร้างระบบบัญชีงบประมาณเพิ่มเติม

ภาพสไลด์หน้าแรกเลื่อนด้วยลูกศรหรือปัดบนมือถือ ภาพกิจกรรมผลงานเลื่อนซ้ายขวาในแกลเลอรี โดยไม่เลื่อนอัตโนมัติเพื่อไม่รบกวนการอ่าน ไฟล์ PDF มีหน้าดูในเว็บและลิงก์เปิด/ดาวน์โหลด หาก browser ไม่รองรับ PDF ใน iframe ให้เปิดจากลิงก์เอกสารแทน

### CSV ตัวแทนห้อง

ต้องมีหัวคอลัมน์ `year,roll,name,class` ใช้ UTF-8 และใส่ปี พ.ศ. เช่น:

```csv
year,roll,name,class
2569,00123,กรอกชื่อจริงก่อนนำเข้า,5/1
```

ใช้ปีเดียวหรือหลายปีในไฟล์เดียวได้ ระบบตรวจทุกแถวและแสดงตัวอย่าง 10 แถวแรกก่อนให้ยืนยัน สูงสุด 5,000 แถวหรือ 5 MB หากรหัสซ้ำในปีเดียวกันหรือรูปแบบผิดจะไม่บันทึกทั้งชุด การนำเข้าไม่ได้เขียนทับข้อมูลที่มีแล้ว

หากเปิด CSV ด้วย Excel ต้องตั้งคอลัมน์ `roll` เป็น Text ก่อนแก้ไข เพื่อไม่ให้ Excel ลบศูนย์นำหน้าตั้งแต่ก่อนอัปโหลด ควรเก็บสำเนาไฟล์ก่อนเปลี่ยนข้อมูลจำนวนมาก

## ตารางและคอลัมน์

ทุกตารางมี `id` ชนิด UUID เป็น primary key ส่วน `new.no` เป็นเลข identity และ `ANACC.no` จัดสรรโดย trigger พร้อม transaction lock รายปี ไม่มีการรันเลขที่หน้าเว็บซึ่งอาจชนกันเมื่อหลายคนบันทึกพร้อมกัน

| ตาราง | คอลัมน์นอกเหนือจาก id |
|---|---|
| `admin` | username, name, role, active |
| `Home` | photo, caption, sort_order |
| `newstat` | name, photo, url, start_at, end_at, dateline |
| `botton` | photo, meg, url, sort_order |
| `significance` | title, mag, url |
| `hoop` | title, mag, url |
| `anthority` | title, mag, url |
| `mamberNACC` | year, photo, name, class, position |
| `ANACC` | year, no, roll, name, class |
| `new` | no, url, name, type, mag, regisname, timestamp |
| `Certificate` | kind, date, name, from, Award, url, รูปกิจกรรม, ระดับรางวัล, ประเภทสิทธิ์เหรียญรางวัล, ประเภทเหรียญรางวัล, ชื่อผลงาน, หน่วยงานที่รับผิดชอบ, วันที่ได้รับ, ผู้ที่ได้รับรางวัล, ครูที่ปรึกษา |
| `plan` | name, ร่าง, เสนอ, ดำเนินการ, แล้วเสร็จ, ผู้รับผิดชอบ, regisname, url |
| `culecculum` | name, url, regisname |
| `tammanun` | name, url, regisname |
| `law` | name, url, regisname |
| `statis` | brand, timestamp |

`Certificate.kind` แยก `certificate` และ `award` เพื่อไม่ให้ข้อมูลเกียรติบัตรปะปนกับผลงาน และแยกคอลัมน์ “ครูที่ปรึกษา” ออกจาก “ผู้ที่ได้รับรางวัล” เพื่อไม่ให้ข้อมูลสองกลุ่มทับกันตามข้อความที่ซ้ำในต้นฉบับ

ช่องไฟล์หลายรายการใช้ JSONB array เพื่อรองรับชื่อไฟล์และชนิดไฟล์อย่างชัดเจน ไม่เก็บหลาย URL ต่อกันเป็นข้อความ:

```json
[
  {
    "url": "https://YOUR_PROJECT.supabase.co/storage/v1/object/public/public-files/USER_UUID/FILE_UUID.pdf",
    "name": "ชื่อเอกสาร.pdf",
    "type": "application/pdf",
    "path": "USER_UUID/FILE_UUID.pdf"
  }
]
```

วันที่และเวลาเก็บเป็น `date` หรือ `timestamptz` เพื่อเรียงและค้นหาได้ถูกต้อง แล้วค่อยแสดงผลเป็นภาษาไทย พ.ศ. และเขตเวลา `Asia/Bangkok` แทนการเก็บวันที่ไทยเป็นข้อความซึ่งเรียงลำดับยาก

## Favicon และ .setFaviconUrl

หน้า GitHub Pages ใส่ `<link rel="icon" href="./assets/logo.png">` และ apple-touch-icon โดยใช้โลโก้จาก Drive ID ที่ให้มา ซึ่งดาวน์โหลดไว้ใน `assets/logo.png` แล้ว จึงไม่ต้องพึ่งลิงก์ Drive ในการโหลดตราหลักทุกครั้ง

เมธอด `.setFaviconUrl()` เป็นของ `HtmlOutput` ใน Google Apps Script ไม่ใช่ JavaScript ที่รันบน GitHub Pages ตาม [เอกสาร HtmlOutput ของ Google](https://developers.google.com/apps-script/reference/html/html-output) จึงแนบ `AppsScript-optional.gs` ที่เรียก `.setFaviconUrl(LOGO_URL)` ให้ต่างหาก หากจะใช้ wrapper บน Apps Script ให้เปลี่ยน URL GitHub Pages ในไฟล์นั้นก่อน ไม่ต้องติดตั้ง wrapper เพื่อใช้งานเว็บไซต์หลัก

## สถิติ ความเป็นส่วนตัว และข้อจำกัด

- **จำนวนผู้ชม:** นับการเปิดหน้าหลักหนึ่งครั้งต่อการโหลดเอกสาร ไม่ใช่ผู้ใช้งานไม่ซ้ำ เปลี่ยนเมนูแล้วกลับหน้าแรกภายในเอกสารเดิมไม่นับซ้ำ แต่รีเฟรชนับใหม่
- **อุปกรณ์:** เก็บประเภทหรือรุ่นเท่าที่ browser เปิดเผย ไม่รับประกันรุ่นเครื่องที่แน่นอน โดยเฉพาะ iPhone และคอมพิวเตอร์ ไม่เก็บ IP/GPS ในโค้ดนี้
- **สถิติส่วนตัว:** ปิดสิทธิ์อ่าน `statis` โดยตรงสำหรับผู้ชมและเจ้าหน้าที่ทั่วไป อ่านยอดรวมได้เฉพาะ RPC `site_stats()`
- **การปั่นยอด:** RPC `record_visit` เปิดให้ผู้ชมเรียกได้ตามงานสถิติทั่วไป จึงยังไม่ใช่ระบบ analytics ที่ป้องกัน bot หากต้องใช้ยอดเป็นตัวชี้วัดทางการ ควรเพิ่ม rate limit/CAPTCHA ที่ Edge Function หรือ gateway
- **ข้อมูลผู้เยาว์:** รายชื่อ รหัสนักเรียน รูปภาพ และไฟล์ที่เผยแพร่เป็นสาธารณะ ต้องให้โรงเรียนตรวจสิทธิ์และความยินยอมก่อนนำข้อมูลจริงขึ้น
- **การบำรุงรักษา:** เจ้าของโปรเจกต์ควรตั้งระยะเวลาเก็บ log, สำรองข้อมูล, ตรวจ quota และใช้ไฟล์ภาพขนาดเหมาะสม
- **บริการภายนอก:** Google Fonts และ Google Maps ต้องใช้อินเทอร์เน็ต ถ้าแผนที่ฝังถูกบล็อก ยังมีลิงก์ “ดูเส้นทาง” เปิด Google Maps ภายนอก
- **รูปจาก Drive:** รองรับลิงก์ไฟล์ Drive ที่เปิดสาธารณะ แต่ไฟล์ส่วนตัวหรือสิทธิ์ไม่พอจะโหลดไม่ได้ แนะนำอัปโหลดผ่าน Supabase Storage สำหรับภาพเนื้อหา

## เมื่อติดปัญหา

- **ยังเห็นแถบตัวอย่าง:** ตรวจ `connected: true` ใน config.js และ commit ไฟล์ที่แก้ขึ้น GitHub แล้ว
- **ไม่พบตาราง / permission denied:** ตรวจว่า SQL รันในโปรเจกต์ตรงกับ config, ติดตั้งครบ และไม่ได้ปิด RLS เพื่อแก้ปัญหาเฉพาะหน้า
- **ล็อกอินไม่ผ่าน:** ตรวจอีเมล `username@pkjunior.local`, password, Auto Confirm, แถว admin ที่ UID ตรงกัน และ `active = true`
- **เพิ่มผู้ใช้ไม่ได้:** ตรวจชื่อฟังก์ชัน `manage-users`, JWT setting และ logs ใน Edge Functions โดยไม่ส่งรหัสผ่านหรือ service-role key ให้บุคคลอื่น
- **อัปโหลดไฟล์ไม่ได้:** ตรวจ bucket `public-files`, MIME type, ขนาดไฟล์ และสิทธิ์ admin/nacc
- **เว็บไม่มี CSS/โลโก้:** ตรวจว่า `index.html` อยู่ root และอัปโหลดโฟลเดอร์ `assets` กับ `vendor` ครบ ไม่แก้ชื่อไฟล์ตัวพิมพ์ใหญ่/เล็ก
- **ไม่มีข่าวแสดง:** ระบบไม่สร้างข่าวหรือบุคลากรสมมติ ให้เพิ่มเนื้อหาจริงผ่านระบบเจ้าหน้าที่
- **ประกาศไม่ขึ้น:** ตรวจ start/end เวลาไทยและเวลาปัจจุบัน ถ้าพ้นช่วงแล้วระบบจะซ่อนโดยตั้งใจ
