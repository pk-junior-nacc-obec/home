## ขั้นตอนที่ 1 — ตรวจสอบ Supabase (มีโปรเจกต์อยู่แล้ว)

โปรเจกต์ Supabase ของคุณ (`baprjszsaixaexpyyovs`) **ตรวจสอบแล้วว่ามีตารางครบและ RPC ทำงานปกติ** จึงใช้งานได้ทันที หากเพิ่งสร้างโปรเจกต์ใหม่ ให้ทำตามนี้

1. เข้า [supabase.com](https://supabase.com) → สมัคร/เข้าสู่ระบบด้วย GitHub
2. กด **New project** → เลือก Organization → ตั้งชื่อ เช่น `pk-junior-nacc`
3. ตั้ง **Database Password** (จดไว้ให้ดี ไม่ต้องใส่ในไฟล์เว็บ) → เลือก Region ใกล้ไทย เช่น Singapore → **Create new project**
4. รอสร้างเสร็จ (1–2 นาที) → เข้าเมนู **Project Settings → API**
   - **Project URL** คือค่า `supabaseUrl` ใน `config.js`
   - ค่า **Project ID** จะอยู่ใน URL นั้น (เช่น `baprjszsaixaexpyyovs`)
   - แท็บ **API Keys** → คัดลอกค่า **Publishable key** (ขึ้นต้นด้วย `sb_publishable_`) ใส่เป็น `publishableKey` ใน `config.js`
   - ห้ามนำ `service_role` หรือ `sb_secret` ขึ้น GitHub เด็ดขาด

## ขั้นตอนที่ 2 — สร้างตารางด้วย SQL Editor

1. ในแดชบอร์ด Supabase กดเมนูด้านซ้าย **SQL Editor** → **New query** (ไอคอน +)
2. เปิดไฟล์ `supabase-schema.sql` ในโปรเจกต์นี้ → คัดลอกโค้ดทั้งหมด → วางในช่อง SQL Editor
3. กดปุ่ม **RUN** (หรือ Ctrl/Cmd + Enter) แล้วรอข้อความ `Success. No rows returned`
4. ตารางทั้งหมดจะปรากฏในเมนู **Table Editor**: `Home`, `newstat`, `botton`, `significance`, `hoop`, `anthority`, `mamberNACC`, `ANACC`, `new`, `Certificate`, `plan`, `culecculum`, `tammanun`, `law`, `statis`, `admin`
   - ทุกตารางมีคอลัมน์ `id` (UUID) ไว้อ้างอิงตอนแก้ไข
   - `new.no` และ `ANACC.no` รันเลขอัตโนมัติ (`new` รันต่อเนื่องทั้งตาราง, `ANACC` เริ่มนับ 1 ใหม่ทุกปีการศึกษา)
   - คอลัมน์ "ผู้บันทึก" (`regisname`) และ "วัน-เวลา" (`timestamp`) ระบบกำหนดให้เองจากเซิร์ฟเวอร์ แก้ไขไม่ได้
   - สำหรับ**ฐานข้อมูลใหม่** สคริปต์นี้ติดตั้งครบในครั้งเดียว ส่วน**ฐานข้อมูลเดิม**รันซ้ำได้โดยไม่ลบข้อมูล (ใช้ `IF NOT EXISTS` / `DROP FUNCTION IF EXISTS` / `ADD COLUMN IF NOT EXISTS`) แต่โปรดอ่านหมายเหตุด้านล่างก่อน

> **สำหรับฐานข้อมูลเดิมที่สร้างจากเวอร์ชันก่อน:**
> 1. สคริปต์จะเติมคอลัมน์ที่ขาด (เช่น `newstat.dateline`) และสร้างฟังก์ชัน/trigger ใหม่ แต่จะ **ไม่ตรวจหรือแก้ไขข้อมูลเดิมที่เก็บผิดกติกา** โดยเฉพาะตาราง `plan`: ถ้ามีแถวที่ติ๊ก "ดำเนินการ" หรือ "แล้วเสร็จ" อยู่ทั้งที่ "เสนอ" ยังไม่ใช่ "ผ่าน" ให้แก้ข้อมูลเหล่านั้นก่อน
> 2. สคริปต์จะลบและสร้างใหม่เฉพาะ**นโยบาย (policy) ที่ชื่อตรงตามที่ระบบนี้ใช้** เท่านั้น — นโยบายเก่าที่มีชื่ออื่นจะคงอยู่ และเนื่องจาก Postgres รวมสิทธิ์ของหลายนโยบายเข้าด้วยกัน นโยบายเก่าที่กว้างกว่าจะยังให้สิทธิ์เกินที่กำหนด โปรดเข้าไปตรวจที่ **Database → Tables → แต่ละตาราง → RLS Policies** แล้วลบนโยบายเก่าที่ไม่ต้องการทิ้ง โดยตรวจเป็นพิเศษที่ตาราง `newstat`, `statis` และ `admin` (ระบบนี้กำหนดให้อ่านได้เฉพาะช่วงที่แสดงผ่าน RPC / ห้ามอ่านตรง และแก้ไขบัญชีได้เฉพาะผ่าน Edge Function)

## ขั้นตอนที่ 3 — สร้างบัญชี Admin คนแรก

1. เมนูซ้าย **Authentication → Users** → กด **Add user → Create new user**
2. กรอก:
   - **Email**: `admin@pkjunior.local` (ระบบล็อกอินด้วย "username" โดยแปลงเป็นอีเมลนี้ให้อัตโนมัติ)
   - **Password**: รหัสผ่านอย่างน้อย 12 ตัวอักษร
   - ติ๊ก **Auto Confirm User**
3. กด **Create user** แล้วคลิกชื่อผู้ใช้ที่เพิ่งสร้าง → คัดลอกค่า **User UID**
4. กลับไป **SQL Editor → New query** วางโค้ดนี้ (แทนที่ `วาง-UID-ตรงนี้` และชื่อ):

```sql
insert into public.admin (id, username, name, role)
values ('วาง-UID-ตรงนี้', 'admin', 'ชื่อ-สกุลของคุณ', 'admin')
on conflict (id) do update set name = excluded.name, role = 'admin';
```

5. กด **RUN** — เสร็จแล้วเข้าระบบเว็บไซต์ด้วย username `admin` และรหัสผ่านที่ตั้งไว้

## ขั้นตอนที่ 4 — ติดตั้ง Edge Function "manage-users" (จัดการบัญชี)

ใช้สำหรับเมนู "การแก้ไขรหัสผู้เข้าใช้" (เพิ่มบัญชี / แก้ชื่อ / รีเซ็ตรหัสผ่าน — สิทธิ์ admin เท่านั้น)

1. เมนูซ้าย **Edge Functions** → **Create a function**
2. ชื่อฟังก์ชัน: `manage-users` (ต้องตรงกับชื่อนี้)
3. ลบโค้ดตัวอย่างออก แล้ววางโค้ดทั้งหมดจากไฟล์ `supabase/functions/manage-users/index.ts`
4. กด **Deploy function** (ตัวแปร `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` ระบบใส่ให้อัตโนมัติ)
5. **ขั้นตอนนี้จำเป็น** เพราะ "การแก้ไขรหัสผู้เข้าใช้" เป็นความสามารถที่กำหนดไว้ของเว็บไซต์นี้ — ถ้ายังไม่ได้ติดตั้ง ส่วนอื่นของเว็บใช้งานได้ปกติ แต่เมนูจัดการบัญชีผู้ใช้จะทำงานไม่ได้

## ขั้นตอนที่ 5 — อัปโหลดขึ้น GitHub Pages

1. สร้าง repository ใหม่บน GitHub (เช่น `pk-nacc-website`) แบบ Public
2. กด **Add file → Upload files** แล้วลากไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้นไป (`index.html`, `styles.css`, `app.js`, `config.js`, โฟลเดอร์ `assets/`) — ห้ามอัปโหลดโฟลเดอร์ `supabase/` ก็ได้ ให้เก็บไว้ในเครื่องเป็นต้นฉบับโค้ด Edge Function
3. กด **Commit changes**
4. เมนู **Settings → Pages** → Build and deployment:
   - Source: **Deploy from a branch**
   - Branch: `main` / โฟลเดอร์ `/ (root)` → **Save**
5. รอ 1–2 นาที เว็บจะอยู่ที่ `https://ชื่อบัญชีgithub.github.io/ชื่อrepo/`

### ใช้โดเมนของโรงเรียน pkjunior.nacc.obec.com

1. เพิ่มไฟล์ `CNAME` (ไม่มีนามสกุล) ใน repository มีข้อความบรรทัดเดียว: `pkjunior.nacc.obec.com`
2. ที่ผู้ให้บริการโดเมน ตั้ง DNS:
   - ระเบียน **CNAME** ของ `pkjunior` → `ชื่อบัญชีgithub.github.io` (หรือ A record ชี้ IP ของ GitHub Pages ตามเอกสาร GitHub)
3. GitHub: **Settings → Pages → Custom domain** ใส่ `pkjunior.nacc.obec.com` → Save และติ๊ก **Enforce HTTPS** เมื่อมีให้ใช้

หมายเหตุ: ระบบเมนูใช้ hash routing ดังนั้นหน้า "ประวัติ" จะเป็น `pkjunior.nacc.obec.com/#/significance` เป็นต้น ไม่ใช่ `/significance` ตรง ๆ เพราะ GitHub Pages ไม่สามารถเขียนกฎเส้นทางฝั่งเซิร์ฟเวอร์ได้ (โครงสร้างเดียวกับที่ใช้กับเว็บไซต์ Google Apps Script เดิมที่ใช้ `setFaviconUrl` — บน GitHub Pages เราตั้ง favicon ด้วย `<link rel="icon" href="./assets/logo.png">` ใน `index.html` ซึ่งเป็นโลโก้ตัวเดียวกับลิงก์ Google Drive ที่กำหนด)

### ข้อกำหนดที่ปรับให้ชัดเจนขึ้นจากต้นฉบับ

- ตาราง `newstat` มีคอลัมน์ `start_at`/`end_at` สำหรับเลือกช่วงเวลาแบบฟอร์ม และระบบสร้างคอลัมน์ `dateline` (ช่วงเวลาเป็นข้อความ) ให้อัตโนมัติเพื่อให้ตรงตามชื่อคอลัมน์ที่กำหนดไว้
- จดหมายข่าวใช้เมนู `/newsletter` (ต้นฉบับพิมพ์ URL ซ้ำกับคำสั่ง `/make` ทั้งสองหน้าจึงถูกแยกเป็นของตัวเอง)
- ตารางผลงานแยกคอลัมน์ "ครูที่ปรึกษา" ออกจาก "ผู้ที่ได้รับรางวัล" เพื่อไม่ให้ข้อมูลสองกลุ่มทับกัน
- จำนวน/ชนิดไฟล์ของแต่ละหน้าถูกจำกัดตามข้อกำหนด (เช่น แผนงาน PDF ได้ 1 ไฟล์, เกียรติบัตร 1–5 ไฟล์) ตรวจที่ฟอร์มก่อนอัปโหลดจริง

## การอัปโหลดรูป/ไฟล์

ไฟล์ทั้งหมดเก็บใน Supabase **Storage → ไฟล์อยู่ใน bucket `public-files`** ระบบแปลงเป็นลิงก์สาธารณะให้อัตโนมัติ หากต้องการลบไฟล์เก่า สามารถเข้าไปลบได้ที่ Storage โดยตรง

## แก้ปัญหาที่พบบ่อย

- **ขึ้น "ตัวอย่างระบบก่อนเชื่อมต่อฐานข้อมูล"** → เปิด `config.js` ตั้ง `connected: true` (และตรวจว่ารัน `supabase-schema.sql` แล้ว)
- **ล็อกอินไม่ผ่าน** → ตรวจว่าสร้างผู้ใช้ใน Authentication แล้ว (ขั้นตอนที่ 3) และแถวในตาราง `admin` มี `active = true`
- **กดเมนูจัดการผู้ใช้แล้ว error** → ยังไม่ได้ติดตั้ง Edge Function `manage-users` (ขั้นตอนที่ 4)
- **รูปไม่แสดง** → ลิงก์รูปต้องเป็น https เต็ม (Google Drive ใช้ลิงก์แบบ `drive.google.com/file/d/...` ได้ ระบบแปลงให้อัตโนมัติ)
- **แก้โค้ดแล้วผู้ใช้เห็นเวอร์ชันเก่า** → เบราว์เซอร์แคชไฟล์เก่าได้ชั่วคราว ให้เพิ่มเลขเวอร์ชันใน `index.html` เช่น เปลี่ยน `./app.js?v=1` เป็น `./app.js?v=2` ทุกครั้งที่แก้ `app.js` หรือ `styles.css`
