# เว็บไซต์ ป.ป.ช.สพฐ.น้อย โรงเรียนภูเขียว

เว็บไซต์โรงเรียนสำหรับ ป.ป.ช.สพฐ.น้อย (PK Junior NACC) โรงเรียนภูเขียว จังหวัดชัยภูมิ
- หน้าเว็บเป็นไฟล์นิ่ง (static) โฮสต์บน **GitHub Pages**
- ฐานข้อมูลใช้ **Supabase** (อ่าน/เขียนข้อมูล และเก็บไฟล์ PDF/รูปภาพ)
- **หน้าตาเว็บเป็นแบบเดิมของระบบเดิมทุกประการ** — เปลี่ยนเฉพาะระบบล็อกอินเป็นแบบใหม่
- ระบบล็อกอิน **ไม่ใช้ Supabase Auth และไม่ใช้ Edge Function** — เทียบ Username/Password กับแผ่นงาน `admin` (คอลัมน์ username, password, name) โดยตรง ผ่านฟังก์ชัน SQL ที่ให้มา และเก็บโทเค็นไว้ในเบราว์เซอร์เพื่อคงสถานะเข้าระบบเมื่อรีเฟรช
- สิทธิ์กำหนดอัตโนมัติจาก username: `admin` ได้สิทธิ์ admin (ดูแลผู้ใช้ด้วย) ชื่ออื่นได้สิทธิ์ nacc

## ไฟล์ในชุดนี้

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บหลัก |
| `styles.css` | สไตล์ของระบบเดิม (โทนขาว–ม่วง–ทอง) |
| `app.js` | โปรแกรมทั้งเว็บ (หน้าแรก เมนู ข่าวสาร หลังบ้าน ฯลฯ) |
| `config.js` | ตั้งค่า Supabase (URL + Publishable Key) |
| `supabase-schema.sql` | สคริปต์สร้างตาราง/คอลัมน์/สิทธิ์ ใน Supabase |
| `README.md` | คู่มือนี้ |

## ขั้นตอนติดตั้ง

### ขั้นที่ 1 — สร้างตารางใน Supabase (ทำครั้งเดียว)

1. เข้า [supabase.com](https://supabase.com) → เปิดโปรเจกต์ของโรงเรียน
2. เมนูด้านซ้ายเลือก **SQL Editor**
3. คัดลอกเนื้อหาไฟล์ `supabase-schema.sql` ทั้งหมด วางลงใน SQL Editor แล้วกด **Run**
4. รอจนขึ้นว่าสำเร็จ (Success) — ระบบจะสร้างตาราง คอลัมน์ สิทธิ์การเข้าถึง และพื้นที่เก็บไฟล์ให้ครบอัตโนมัติ

**บัญชีเริ่มต้น:** `username: admin` / `password: admin1234`
**กรุณาเข้าสู่ระบบแล้วเปลี่ยนรหัสผ่านทันที** (เมนู 3 ขีด → เข้าสู่ระบบ → หลังบ้าน → การแก้ไขรหัสผู้ใช้ → เปลี่ยนรหัสผ่านของฉัน)

### ขั้นที่ 2 — อัปโหลดเว็บไซต์ขึ้น GitHub Pages

1. สร้าง repository ใหม่บน GitHub (ตั้งชื่อ เช่น `pk-junior-nacc` หรือ `ชื่อบัญชี.github.io`)
2. อัปโหลดไฟล์ทั้ง 5 ไฟล์ (`index.html`, `styles.css`, `app.js`, `config.js`, และ `README.md` ถ้าต้องการ) ไปที่ branch `main`
3. เข้า **Settings → Pages** → Source เลือก `main` branch กด Save
4. รอสักครู่ จะได้ลิงก์เว็บไซต์ `https://ชื่อบัญชี.github.io/ชื่อ-repository/`

> ถ้าใช้ชื่อ repository ว่า `ชื่อบัญชี.github.io` เว็บจะอยู่ที่ `https://ชื่อบัญชี.github.io/` โดยตรง

### ขั้นที่ 3 — ใช้งาน

- เปิดเว็บไซต์ ระบบจะดึงข้อมูลจาก Supabase มาแสดงอัตโนมัติ
- กด **เข้าสู่ระบบ** (มุมบนขวา หรือท้ายเว็บ) เพื่อเข้าหลังบ้านเพิ่ม/แก้ไขข้อมูล

## สิทธิ์ผู้ใช้งาน

| บัญชี | สิทธิ์ |
|---|---|
| `admin` | จัดการได้ทุกส่วน รวมถึง **การแก้ไขรหัสผู้ใช้** (เพิ่มบัญชี/รีเซ็ตรหัสผ่าน) |
| บัญชีอื่น (nacc) | จัดการประวัติ ข่าวสาร กลุ่มงาน สารสนเทศ และหน้าแรก ได้ แต่ไม่มีเมนูการแก้ไขรหัสผู้ใช้ |

บัญชีใหม่ที่เพิ่มเข้ามา (นอกจาก `admin`) จะเป็นสิทธิ์ nacc ทั้งหมดตามที่กำหนด

## หมายเหตุสำคัญ

1. **ความปลอดภัยของรหัสผ่าน:** ระบบนี้ไม่ใช้ Supabase Auth ตามที่กำหนด — ตาราง `admin` (คอลัมน์ username, password, name ตามที่กำหนด) ถูกปิดไม่ให้อ่านโดยตรง ตรวจสอบได้เฉพาะผ่านฟังก์ชัน login และการเขียนข้อมูลทุกครั้งต้องมี token จากการ login เท่านั้น **รหัสผ่านจะถูกเก็บเป็นแฮช SHA-256 ไม่ใช่ข้อความธรรมดา** (กรอกที่หน้าเว็บเหมือนเดิม ระบบแปลงให้เอง และถ้ามีข้อมูลเดิมจากระบบเก่าสคริปต์จะแปลงให้อัตโนมัติ) อย่างไรก็ตาม ระดับความปลอดภัยเหมาะกับเว็บไซต์โรงเรียนเท่านั้น ไม่ควรเก็บข้อมูลอ่อนไหว
2. **รันสคริปต์ซ้ำได้และปลอดภัยกับข้อมูลเดิม:** สคริปต์ออกแบบให้รันซ้ำกี่ครั้งก็ได้ และรันทับตารางเดิมได้โดยไม่ทำข้อมูลหาย (เพิ่มเฉพาะคอลัมน์ที่ขาด ลบ policy/ฟังก์ชันเก่าที่ชน แปลงรหัสผ่านข้อความธรรมดาเดิมเป็นแฮช และไม่เขียนทับบัญชีที่มีอยู่แล้ว)
3. **ชื่อคอลัมน์ภาษาไทยยาวพิเศษ:** PostgreSQL (รวม Supabase) จำกัดชื่อคอลัมน์ที่ 63 ไบต์ — คอลัมน์ "ประเภทสิทธิ์เหรียญรางวัล" ยาวเกินขีดจำกัด จะถูกย่อเหลือ "ประเภทสิทธิ์เหรียญราง" โดยอัตโนมัติ (ข้อมูลทำงานปกติทุกอย่าง ทั้งบันทึก แสดงผล และกรอกฟอร์ม — สังเกตได้เฉพาะตอนเปิดดูตารางในแดชบอร์ด) โค้ดหน้าเว็บจัดการเรื่องนี้ให้แล้ว
4. **โดเมน `pkjunior.nacc.obec.com`:** ชื่อพวกนี้ใช้เป็นชื่อหน้าเว็บภายในระบบเท่านั้น (เช่น `#/announce` = หน้าประกาศ) การใช้งานโดเมนจริงต้องมีเจ้าของโดเมน `nacc.obec.com` มาตั้ง DNS (CNAME) ชี้มาที่ GitHub Pages ให้
5. **จดหมายข่าว:** ในสเปกต้นฉบับเขียนเส้นทาง `/make` ซ้ำกับคำสั่ง ระบบจึงใช้ `#/newsletter` แทน
6. **งบประมาณ:** ยังเป็นส่วน "รอพัฒนา" ตามที่กำหนด
7. **การอัปโหลดไฟล์:** อัปโหลดได้เฉพาะ PDF และรูปภาพ (ไม่เกินไฟล์ละ 20 MB) ลง bucket `public-files` — ข้อจำกัดทางเทคนิค: นโยบายของที่เก็บไฟล์อาจตรวจ token คนอัปโหลดไม่ได้ จึงเปิดให้อัปโหลดไฟล์ประเภทที่กำหนดไว้ได้โดยตรง แต่ยังตรวจชนิดไฟล์ (PDF/รูปเท่านั้น) และการลบไฟล์ทำได้เฉพาะผู้ล็อกอิน

## โครงสร้างหน้าเว็บ (hash routing)

| เส้นทาง | หน้า |
|---|---|
| `#/` | หน้าแรก (สไลด์ ประกาศ ปุ่มลัด ข่าวสาร สถิติ) |
| `#/significance` `#/hoop` `#/anthority` | ที่มาและความสำคัญ / เจตจำนง / อำนาจหน้าที่ |

| `#/announce` `#/information` `#/make` `#/newsletter` | ประกาศ / ประชาสัมพันธ์ / คำสั่ง / จดหมายข่าว |
| `#/certificate` `#/award` | ทะเบียนเกียรติบัตร / ผลงาน |
| `#/plan` `#/mony` `#/culecculum` | นโยบายและแผน / งบประมาณ / หลักสูตร |
| `#/tammanun` `#/law` | ธรรมนูญ / กฎหมาย |
| `#/login` `#/admin/...` | เข้าสู่ระบบ / หลังบ้าน |

## ตารางข้อมูลใน Supabase (สรุป)

ทุกตารางมีคอลัมน์ `id` (uuid) ใช้อ้างอิง

| ตาราง | คอลัมน์หลัก |
|---|---|
| `admin` | username, password, name |
| `Home` | photo, caption, sort_order |
| `newstat` | name, photo, url, dateline (ช่วงเวลาแสดง) |
| `botton` | photo, meg, url, sort_order |
| `significance` / `hoop` / `anthority` | title, mag, url |
| `mamberNACC` | year, photo, name, class, position |
| `ANACC` | year, no, roll, name, class |
| `new` | no, url, name, type, regisname, timestamp, mag |
| `Certificate` | kind, date, name, from, Award, url + คอลัมน์ผลงาน (ชื่อภาษาไทย; คอลัมน์ "ประเภทสิทธิ์เหรียญรางวัล" จะถูก PostgreSQL ย่อเหลือ "ประเภทสิทธิ์เหรียญราง" อัตโนมัติ — ใช้งานได้ปกติ) |
| `plan` | name, ร่าง, เสนอ, ดำเนินการ, แล้วเสร็จ, ผู้รับผิดชอบ, regisname, url |
| `culecculum` / `tammanun` / `law` | name, url, regisname |
| `statis` | brand, timestamp (สถิติการเข้าชม) |

ระบบอัตโนมัติฝั่งฐานข้อมูล: รันเลขลำดับให้เอง (กันเลขชนเมื่อบันทึกพร้อมกัน) ประทับชื่อผู้บันทึกและเวลาให้เอง ล็อกช่องลำดับ/ประเภท/ผู้บันทึก/เวลาเมื่อแก้ไขข่าว บังคับขั้นตอน Timeline (ไม่ผ่าน = ห้ามดำเนินการ/แล้วเสร็จ) และตรวจ token ก่อนอนุญาตให้เขียนข้อมูลทุกครั้ง
